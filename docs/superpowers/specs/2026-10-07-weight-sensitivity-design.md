# 权重敏感性分析（建议转折点）设计说明

## 目标与边界

结果页新增「权重敏感性」：选定一个价值维度，观察它的归一化权重从 0% 变化到 100% 时，在**完全沿用当前方案（选项、影响值、可逆性）、同一时间口径（1/5/10 年，30%/40%/30%）、同一评分与建议规则（总分四舍五入、前两名差距 <5 分为并列）**的前提下，建议会在哪些区间成立、在什么位置发生转折。

约束：

- 不预测未来、不引入新规则、不改动任何评分公式；敏感性结论必须能由现有规则引擎逐点复算得到。
- **不允许靠图形插值“猜”名次**：名次只能来自规则引擎对具体权重的真实复算；解析线性公式仅用于决定“哪里值得复算”。
- **并列是一等公民**：并列结果以区间显示，不强行画唯一胜者；并列与并列之间也可能不同（并列的选项集合不同）。
- 试探权重**不覆盖**当前方案权重；用户显式确认才应用；重新编辑方案后旧敏感性结果立即失效。

## 问题形式化

权重归一化为百分比且四个维度之和恒为 100%。选定维度 k，令其归一化权重为 x∈[0,100]（滑块粒度为 0.1%，x 为 0.1 的整数倍，共 1001 个可达点）。其余三个维度合计 100−x，其相对分配方式必须由用户选择（见下）。每个 x 对应一组确定权重，用现有 `analyzeDecision` 复算，得到「建议签名」。

建议签名：按引擎排序后的选项 id 序列 + 胜者标记。现有建议规则只有两种输出：

1. 唯一胜者（前两名差距 ≥5）：签名含 winnerId；
2. 并列提示（差距 <5）：签名为「前两名并列」，无 winnerId。

因此签名具体化为 `winnerId 或 'tie:'+第一id+','+第二id`（id 按引擎排序后的顺序）。签名发生变化的位置即为**转折点**；相邻转折点之间为**建议区间**。

## 其余权重的调整方式

增加一个维度必然挤占其他维度，必须明确“从谁那里、按什么比例让出份额”。提供两种可解释的方式，用户在结果页显式选择：

### A. 等比缩放（默认，推荐）

其余三维度保持彼此间的**相对比例**不变：

```
w_j(x) = (100 − x) · b_j / B,   j ≠ k,   B = Σ_{j≠k} b_j
```

其中 b_j 是**当前（已归一化）权重**。含义：你只是在“抬高 k”，其余偏好结构不变。

退化：B = 0（当前只有 k 一个维度有权重）时无相对比例可保持，自动回退到「平均分摊」，并在结论中明确提示“其余维度当前权重均为 0，已按均摊处理”。

### B. 平均分摊

k 增加的份额由其余维度均摊：

```
w_j(x) = b_j − (x − b_k) / 3,   j ≠ k
```

下界为 0；当某些维度率先被挤到 0 后，剩余份额由仍未到 0 的维度继续均摊（注水式确定算法）。含义：抬高 k 时对其余维度一视同仁。

两种方式都在 0.1% 整数单位（tenths，总和恒为 1000）上按**最大余数法**分配，保证 Σw=100% 且与逐点复算时的输入完全一致；结果标注实际使用的调整方式与 0.1% 取整说明。

## 评分结构（沿用现有规则，仅作算法分析）

对选项 e、时间跨度 h，现有规则为

```
S_e,h(w) = round( Σ_k ((5−i_e,k)/10) · w_k · t_h,k ) + I_e,h,   截断到 [0,100]
T_e(w)   = round(0.3·S_e,1 + 0.4·S_e,5 + 0.3·S_e,10)
```

其中 I_e,h（不可逆成本）与权重无关。关键性质：

- 在截断区间内，S_e,h 关于权重向量是**线性**的，因而关于 x（沿任一种调整路径）也是线性的；
- T_e 在同一截断区域内关于 x 线性；
- 任意两个选项 e,f 的总分差 D_ef(x)=T_e−T_f 是**分段线性**函数，折线仅发生在某个 S_e,h 碰到 0 或 100 截断边界处；
- 建议签名的全部变化都由这些量驱动：**名次翻转（D_ef 过 0）**与**并列进入/离开（前两名 D 过 ±5）**。

这些性质只用于计算“哪里必须复算”，所有呈现的名次/总分仍然是引擎真实输出。

## 寻找转折点的方法与比较

### 方法一：固定步长扫描

在 x∈[0,100] 上以固定步长 δ 逐点复算并比较签名。

| 步长 | 复算次数 | 分辨率 | 窄区间遗漏 |
|---|---|---|---|
| 5% | 201 | 5% | **会遗漏宽度 <5% 的并列带与折返**：某步长内两次翻转（A→tie→A 或 A→tie→B→…）在两端签名相同，完全不可见 |
| 1% | 101 | 1% | 仍会遗漏 <1% 的窄并列带；转折边界误差 ≤δ |
| 0.1% | 1001 | 0.1%（滑块可达粒度） | **无遗漏**：恰好覆盖全部可达权重点，转折边界精确到 0.1% |

固定步长的代价是点数的线性函数；缩小步长同时提高计算量。5% 步长对“唯一胜者互换”的大区间够用，但并列带常常很窄（只差 5 分阈值，D 略陡即只有零点几个百分点宽），这是最容易被遗漏、也最不该被遗漏的信息（漏掉并列等于替用户强画了唯一胜者）。

### 方法二：粗扫 + 逐步细化（纯二分/细分）

先用大步（5%，21 点）扫描，只在相邻签名不同的格子里细分（二分或递归中点）。

- 计算量：典型情况下只需在少数格子里细分，约 30–80 次复算；
- 致命缺陷：**只能发现“粗采样两端已经不同”的格子**。若转折完全发生在一个 5% 格子内部（窄并列带、折返），两端签名相同，根本不会触发细化——遗漏问题与方法一在 5% 步长下相同；
- 纯二分还假定格子内单调/最多一次转折，本问题不保证（分段线性可有多个折点、多次进出并列）。

即：逐步细化降低了计算量，却**不降低窄区间遗漏风险**，反而容易让人误以为“细化过就完整了”。

### 方法三：解析候选 + 定向细化（本方案默认「智能细化」）

不依赖“相邻签名是否不同”来决定哪里值得查，而是用分段线性的**未取整**结构找出所有“可能发生事件”的位置，再对这些位置附近做 0.1% 全粒度复算：

1. **粗采样**：对 x=0,5,10,…,100（21 点）真实复算，得到每个选项的总分，建立排序骨架；
2. **解析定位候选事件**：对每个选项对 (e,f)，用粗格子两端的**未取整原始分**（`rawTotal`，不经过四舍五入与截断后的外层取整；截断区域内为线性）求出下列阈值的理论穿越位置：
   - D_ef = 0（名次翻转）；
   - D_ef = ±5（并列带边界，对应外层取整后差距进入/离开 <5）。
   另外把 0 分 / 100 分截断可能改变线性式的格子（用未取整 horizon 原始分是否接近 0、100 判定）也标记为候选；
3. **加保护带**：
   - 穿越点（D=0 / D=±5）两侧各 ±2.5 个分差单位（换算为 tenths 宽度）。2.5 = 外层总分四舍五入 0.5 + 三个 horizon 各自四舍五入经 0.3/0.4/0.3 混合后的最坏 2.0；
   - 未穿越但**整段贴近**阈值的格子，只细扫“截断后 D(x) 距阈值 ≤2.5”的子区间（分段线性，用端点斜率求其与粗格的交集），不扩大到整格；
   - D 在格内恒为 ±5 时整格细扫；D 恒为 0 表示该对选项全程相等、不可能在格内因这一对改变结果，可安全跳过；
   - 含 0/100 截断 kink 的格子不满足线性，**整格细扫**（kink 用未截断原始分是否跨越 0/100 ±2.5 带判定）；
4. 其余粗格子区间内不包含任何候选事件（无任何选项对在其内穿越 0 或 ±5、无截断折点），可证明签名恒定，取区间内一个代表点复算后沿用，不再逐点复算；
5. 汇总所有 0.1% 复算点 + 被证明恒定的区间，合并相邻同签名段，输出区间与转折点。

计算量：实测随机方案中位数约 300–550 次复算（全程并列/无事件时只需 21 个粗点，最坏情况下候选遍布全域会退化为约 1001 次，此时自动等同精扫，不牺牲正确性）；**无窄区间遗漏**（候选由公式穷举，而非由采样结果触发），转折边界精确到 0.1%。正确性由 600 组随机方案下与 0.1% 全量精扫的逐点签名一致性测试守护。

### 方法四：0.1% 全量精扫（「精确扫描」，作为对照与兜底）

固定 0.1% 步长，1001 次复算。点数恰为滑块可达权重的总数，因此结果在可达粒度上精确无遗漏，作为智能细化的正确性基准；UI 可一键切换到该模式核对，智能细化也在候选数异常时自动回退到它。

### 方法比较小结

| 做法 | 典型复算量 | 窄并列带 | 格子内折返 | 边界精度 | 结论 |
|---|---|---|---|---|---|
| 固定步长 5% | 21 | 遗漏 | 遗漏 | 5% | 仅适合概览，不能作为结论 |
| 固定步长 1% | 101 | 可能遗漏 | 可能遗漏 | 1% | 折中 |
| 固定步长 0.1% | 1001 | **无遗漏** | **无遗漏** | 0.1% | 精确基准，计算量最大 |
| 粗扫 + 纯细分 | 30–80 | 仍遗漏 | 单调假设下可，否则出错 | 0.1% | 计算小但有系统性盲区 |
| 解析候选 + 定向细化（默认） | 21（恒定）/中位约 300–550（最坏 1001） | **无遗漏** | **无遗漏**（每对每阈值各自求解，kink 格整查） | 0.1% | 无事件时最省；高拥挤随机方案下偏向精扫以保正确 |

## 输出模型

- `SensitivityReport`：选定维度、调整方式（proportional/even）、量化后的基准权重、扫描模式、实际复算点数、`segments: SensitivitySegment[]`、`turningPoints`、解释 notices。
- `SensitivitySegment`：`startX/endX`（0.1% 单位的闭区间，相邻区间共享端点时转折值属于右侧新区间，UI 明确标注“恰在该值时为新建议”）、`winnerIds`（唯一胜者 1 个；并列 2 个）、`tie: boolean`、`verified`（该区间是否全部由 0.1% 复算覆盖；粗扫模式的间隔段为 `false`，显示为“未验证间隔”而不是猜一个胜者）。
- `TurningPoint`：x 值、变化前后的人类可读描述。

区间条（内联 SVG）按真实区间宽度绘制；唯一胜者段用选项色，并列段用两选项色的斜纹，未验证间隔段用灰色斜纹。不做跨点的曲线插值排名。

## 可解释性要求

- **零权重**：x=0 端点单独成段并标注。此时选中维度完全不参与评分（等价于把该维度移出价值体系），结论只反映其余维度；若其余维度也全为 0（仅 even 路径下 x=0 且基准退化时可能接近），规则引擎会拒绝计算，界面转为提示“请至少关注一个维度”，不产生建议。
- **极端偏好**：x=100 端点单独成段：单一维度独裁。常出现“该维度影响值最高的选项必胜”或极端并列，文案直接说明这是“只看该维度”的结果。
- **多个转折**：全部转折点逐条列出（“在约 a% 时由 X 与 Y 并列转为 Y 独占；在约 b% 时转回…”），区间条完整呈现反复进出并列/易主的形态，不合并、不简化。
- **全程无转折**：明确显示“在 0–100% 全程，建议始终为…”。
- **并列区间**：文案与图都显示并列的两个名字及区间宽度；不用单一颜色/单一胜者表达。
- 调整方式退化、0.1% 量化、复算点数与模式都在结论中可见。

## 试探、套用与失效

- 区间条或转折点列表可把任意 x「临时套用」：用该 x 对应的权重调用同一规则引擎生成**预览**（建议、总分、1/5/10 年分），与当前基准并排对比；预览权重不写回 draft。
- 预览区提供「应用为新权重并重推」：用户确认后才 `setWeights + analyze`。
- 任何对方案的编辑（标题/背景/选项/影响值/可逆性/权重）、重新推演、载入其他案例，都会使当前敏感性结果**失效**：结果上覆盖“方案已变化，敏感性结论基于旧版本，请重新生成”，并隐藏试探预览；结果本身不立即删除，但不再可套用。以 `sensitivityVersion`（随 touch 递增、analyze 后刷新）与报告内版本号比对实现。

## 架构落点

- `src/core/analysis-service.ts`：额外导出 `rawHorizonScore / rawTotalScore`（现有公式的未取整形式）与 `analyzeWithWeights(draft, weights)`；现有 `analyzeDecision` 行为保持不变。
- `src/core/sensitivity-service.ts`（新增）：基准量化、`reweight`、`analyzeAt`、`runSensitivity`（coarse/adaptive/exact）、区间合并、转折点、解释文案；纯函数，不读浏览器状态。
- `src/ui/components/SensitivityPanel.vue`（新增）：维度与调整方式选择、模式、生成、区间条、转折列表、试探预览与应用。
- `ResultPanel.vue` / `App.vue` / `useDecisionStudio.ts`：接入面板、版本号与 apply 事件。
- 打印样式中隐藏试探交互（敏感性结论本身可保留为静态区间摘要，本版先整体隐藏面板）。

## 测试与验收

- 权重再分配：等比/均摊在一般、退化（B=0）、某维度率先归零情形下总和恒为 1000 tenths；x=0/100 端点正确。
- 构造或随机搜索一个含「<5% 窄并列带」的方案：5% 固定粗扫遗漏该带（verified=false 或直接看不到并列），智能细化与 0.1% 精扫都能找到且区间一致。
- 自适应与精扫在数百个随机方案上**签名序列完全一致**（fuzz 等价性）。
- 并列区间、零权重、极端偏好、多转折文案；试探不改写权重；编辑后失效。
- `npm test`、`npm run build` 通过。
